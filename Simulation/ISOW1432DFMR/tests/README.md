# Independent qualification tests

The initial tests were written from the user specification and TI SLLSF86D Revision D (August 2026), without reading the model. `initial_manifest.json` preserves the original 44-case freeze (SHA-256 `54a8e1cb1abca1e4d1a610300eae1c929f88692693055524d7302c097866953c`); `manifest.json` lists all later fixtures, roles, unchanged source input hashes, numerical assertion counts and datasheet references. All 20 physical pins are passed in package order. Separate external 0 V links connect each required pair of grounds. The isolated domain is biased at +2 V by the testbench so unintended global-ground references become visible.

Run sequentially while Altium is available and no other MixedSim calculation is running:

```powershell
python tests/run_suite.py --acceptance-only --pad-endpoint
python tests/run_suite.py --only 01_mode_3v3 02_mode_5v
```

The default tester is `C:\Users\Nomatin\projects\Spice Tester\spice_sifter.py` (the current name of Spice Tester); the runner falls back to the legacy `dbur_test.py` when available. `--tester` overrides it. Historical qualification reports retain the hash of the actual earlier CLI. Each JSON can also be passed directly to the tester. Each `.cir` is a standalone netlist including the model by relative path. The Python runner is required for supplemental cross-window current-increase, soft-start/no-early-drive and normalized differential rise/fall checks. Altium is accessed only through the tester.

`01`–`20` map to the requested functional scenarios. `21`–`26` and `37` qualify consumption; `27`–`28` qualify propagation delays; `29`–`30` check floating defaults; `31`–`32` measure Hi-Z and short currents; `33` checks VIO loss; `34` checks both UVLO branches; `35`–`36` check output enable/disable times; `38` qualifies GPIO timing under the Figure7-11 conditions. Static tests use native DC operating point, not a transient substitute. Every test includes an external 10 µF VISOOUT capacitor.

For supply-current qualification, §6.10/6.11 IDD tests use VDD=VIO=5 V, MODE sets the isolated rail. IIO tests separately use VIO=3.3 V. RX has 15 pF, TX has 120 Ω || 50 pF and loopback connects the actual bus outputs to A/B. Alternating 12 Mbit/s data has an 83.333 ns unit interval and 166.667 ns period. 115200 baud uses an 8.680556 µs unit interval and a 17.361111 µs period. ±15% around TI typical currents is the specification's model accuracy target, not a TI production guarantee. Delay targets ±20% and edge targets ±30% around TI typical values are ESTIMATED acceptance bands for this functional model. Guaranteed voltage and current checks use the stated datasheet limits. Invalid 3.3 V to 5 V conversion is unspecified by TI; requiring OFF is an ESTIMATED safe response, not a TI electrical characteristic.

TI §6.9 gives IOS ≤180 mA, while §8.6.2 describes protection at 250 mA; the stricter table limit is tested. GPIO propagation is 227 ns; receiver failsafe at VID=0 and EN=LOW R=HIGH follow Table8-3. Numerical driver-enable checks use Figure7-5's 110 Ω/50 pF fixture; receiver-enable uses Figure7-8's 1 kΩ/15 pF fixture.

Each execution creates a new `Results/<round>/` directory and refuses to overwrite it. Raw native reports and stderr are preserved even for FAIL/ERROR. Summary records SHA-256 of the model, tester and each actual test. Historical failure reports must remain available; a later passing round does not erase earlier results.

After the initial independent freeze, five additional `39_steady_*` fixtures were added to distinguish an early transient from steady supply consumption. They retain the same source conditions and ±15% numerical targets, run to 200 µs, require both 120–140 µs and 180–200 µs mean currents to pass, and additionally require mean-current drift between windows ≤2% of the TI typical target. The original 44 test criteria and their initial manifest hashes remain recorded unchanged.

Current monitors use an F-controlled current source and a 1 Ω resistor, giving 1 V/A. Thus native DBUR measurement units correctly remain **V**, numerically equal to amperes. Derived summary fields explicitly convert those monitor voltages to A/mA. Raw native units and measurements are never rewritten. Native qualification uses installed Altium Designer 24.4.1.13 MixedSim; ngspice screening is supplementary and does not replace it.

Final evidence separates 56 qualified acceptance tests, one additional stress test, and six retained diagnostic fixtures. `Results/acceptance_summary.json` lists every role, source report, replacement and runtime SHA. Initial `18_gpio` actually exercises alternating data at 4 Mbit/s (250 ns unit interval, 500 ns period). Its passing result is supplementary stress evidence, **not** a TI capability claim. The rated 2 Mbit/s GPIO check is `44_gpio_2mbps` (500 ns unit interval, 1 µs period); `38_gpio_timing` separately measures propagation under the 50 kHz Figure7-11 conditions.

The retained diagnostics are initial `03` (an unnecessarily strict OFF requirement for a TI-unspecified invalid supply mode), `06` and `34` (zero bounds without numerical tolerance), and early-window `24` TX currents plus `26` loopback current (activity-estimator startup). Reviewed `40` allows a safe voltage below 4 V but requires TX Hi-Z despite DE=HIGH using external clamps. Reviewed `41` and `45` allow 1 mV numerical zero tolerance. `39_steady_*` replaces early transient currents for consumption acceptance. All original input files and FAIL reports remain unchanged; an original `24` ERROR caused by a test-harness endpoint issue also remains preserved.

The unmodified tester strictly rejects a mean window ending at 5 µs when a simulator exports its final time as 4.9999999999999996 µs. `--pad-endpoint` creates reviewable runtime JSON and `.cir` copies under `tests/runtime/<round>/`, extending only transient stop time 5→5.1 µs or 200→201 µs. All measurement windows, limits and circuit elements remain unchanged; model includes are rebased relatively. Each summary records original and executed input SHA-256 and the exact adaptation. No tester patch or raw-result rewrite is used. Running every historical fixture without `--acceptance-only` intentionally includes retained failures.

Eight additional VISOOUT–VISOIN connection tests (`46`–`53`) passed 97 assertions through the unmodified Spice Tester. `46`–`49` physically omit the supply link in both 3.3 V and 5 V modes, with both input polarities, DE HIGH and RE LOW. Y/Z/R/OUT are externally voltage-clamped and their separate component-port currents must remain within ±1 µA. A 1 MΩ VISOIN reference is an external weak discharge path, not a source of power. VISOOUT must remain nominal while VISOIN stays below 1 mV. `50` toggles D, differential A/B and IN while the link is absent; all four output-port current limits apply throughout the transient. `51` ramps VDD with 10 µF on VISOOUT and verifies that the converter starts but no interface output drives at any time.

`52` and `53` start normally, open only the external supply-link switch at 10 µs and restore it at 100 µs. External 100 nF VISOIN capacitance discharges through 330 Ω. The tests allow continued operation while stored charge keeps VISOIN valid; they check Hi-Z during the discharged interval and normal TX/RX/GPIO operation both before the interruption and after restoration. Four port-current mean/ripple bounds over 60–90 µs prove output Hi-Z despite external biases. These are functional-model tests: the unpowered-VISOIN response and 1 µA test bound are explicitly ESTIMATED, not a TI guarantee of unpowered pin leakage or protection-diode back-power behaviour. Raw evidence is in `Results/native_visoin_followup/`; the previous acceptance ledger is preserved in `Results/before_visoin_followup/`.
